# نظام إجازات المنسوبين

**المملكة العربية السعودية — وزارة الداخلية — المديرية العامة للدفاع المدني**
**إدارة الدفاع المدني بمنطقة المدينة المنورة**

تطبيق ويب من صفحة واحدة (Single-file HTML App) لإدارة إجازات منسوبي مركز تدريب الدفاع المدني بمنطقة المدينة المنورة، مع **قاعدة بيانات سحابية مشتركة (Firebase)**: البيانات وحسابات المستخدمين مشتركة فعليًا بين كل من يملك صلاحية دخول، وتتزامن تلقائيًا وفوريًا مهما كان الجهاز أو المتصفح أو الموقع الذي يُفتح منه الرابط.

## ⚠️ قبل أول استخدام: خطوة إعداد لمرة واحدة

هذا الملف **لن يعمل مباشرة** إلا بعد ربطه بمشروع Firebase مجاني (خدمة تابعة لـ Google). هذه خطوة تقنية بسيطة تُنفَّذ **مرة واحدة فقط**، بعدها يعمل النظام بالكامل من داخل التطبيق نفسه دون أي إعداد إضافي.

**افتح ملف [`FIREBASE_SETUP.md`](./FIREBASE_SETUP.md) في هذه الحزمة واتبع خطواته بالترتيب أولًا.** إن فتحت `index.html` قبل إتمام هذه الخطوة سترى شاشة "لم يتم إعداد قاعدة البيانات بعد" وهذا متوقّع تمامًا.

## المزايا

- **بيانات مشتركة ومتزامنة فوريًا** بين جميع المستخدمين المصرَّح لهم، من أي جهاز أو متصفح أو مكان — لا حاجة لأي خادم يديره صاحب الموقع، فكل شيء يُدار عبر Firebase.
- تسجيل دخول بالبريد الإلكتروني وكلمة المرور، مع نظام صلاحيات بمستويين: **مدير** (صلاحية كاملة) و**مستخدم عرض فقط** (فحص البيانات دون تعديل).
- المدير يستطيع إضافة مستخدمين جدد وتحديد صلاحياتهم من داخل النظام مباشرة (زر "إدارة المستخدمين") — دون الحاجة للرجوع إلى إعدادات Firebase بعد الإعداد الأولي.
- أيقونات لكل شعبة/قسم: شعبة التعليم، شعبة التدريب، شعبة المساندة الإدارية، شعبة أجنحة التدريب، قسم الجودة التعليمية، المكتب.
- داخل كل شعبة (للمدير فقط): اختيار المنسوب ← اختيار نوع الإجازة (عرضية 1-10 أيام / اعتيادية 1-45 يوم) ← تاريخ البدء من تقويم ← حساب تاريخ الانتهاء تلقائيًا ← حفظ.
- **تصنيف تلقائي لحالة كل إجازة**: "قادمة" (لم يحن موعدها بعد) / "إجازة" (جارية الآن) / "منتهية" (انتهت) — ولا يدخل في نسبة "المتمتعين بالإجازة" إلا من كانت حالته "إجازة" فعليًا اليوم.
- نسبة المتمتعين بالإجازة ونسبة المتواجدين تُحسب لحظيًا بحسب تاريخ اليوم.
- **رسم بياني أسبوعي** (من الأحد إلى السبت) يوضح نسبة وعدد المتمتعين بالإجازة يوميًا، لكل شعبة وللمجموع العام، ويتحدّث تلقائيًا مع أي تغيير في البيانات أو التاريخ.
- جدول الإجازات السابقة لكل شعبة مع تصفية حسب المنسوب ونوع الإجازة، وإمكانية الحذف (للمدير فقط).
- صفحة "الإجازات العامة" تجمع كل الشعب: الإجمالي، النسب، الرسم البياني الأسبوعي، وجدول شامل بكل الإجازات.
- استيراد بيانات محلية قديمة (لمن استخدم نسخة سابقة تعتمد على تخزين المتصفح فقط) إلى قاعدة البيانات المشتركة الجديدة، بضغطة واحدة.

## التشغيل

1. أتمم خطوات [`FIREBASE_SETUP.md`](./FIREBASE_SETUP.md) مرة واحدة (إنشاء مشروع Firebase، تفعيل تسجيل الدخول، إنشاء قاعدة البيانات، إنشاء أول حساب مدير، ولصق بيانات الربط داخل `index.html`).
2. انشر `index.html` على GitHub Pages (انظر القسم أدناه)، أو افتحه مباشرة بأي متصفح حديث لتجربته محليًا.
3. سجّل الدخول بحساب المدير الذي أنشأته يدويًا في الخطوة (5) من دليل الإعداد.
4. من زر "إدارة المستخدمين" أضف بقية الموظفين المخوَّلين مباشرة من داخل التطبيق.

### نسيت كلمة المرور؟

اضغط رابط "نسيت كلمة المرور؟" أسفل شاشة الدخول وأدخل بريدك الإلكتروني المسجَّل، وستصلك رسالة من Firebase تحتوي رابط إعادة تعيين كلمة المرور مباشرة (تحقّق من مجلد البريد غير المرغوب فيه إن لم تجدها خلال دقائق).

### إدارة المستخدمين

من حساب المدير، زر "إدارة المستخدمين" أعلى الصفحة يفتح نافذة لإضافة مستخدمين جدد بصلاحية "عرض فقط" (يفحصون الشعب والإحصائيات والجداول دون إضافة أو حذف) أو بصلاحية "مدير" كاملة، وإلغاء صلاحية أي مستخدم عدا نفسك أو آخر حساب مدير في النظام. إلغاء الصلاحية من داخل التطبيق يمنع الوصول فورًا؛ لحذف حساب الدخول (البريد/كلمة المرور) نهائيًا من الأساس، راجع القسم الأخير من `FIREBASE_SETUP.md`.

## ⚠️ ملاحظات أمنية مهمة

- البيانات محفوظة الآن في قاعدة بيانات Firebase السحابية التابعة لحسابك أنت (وليس في متصفح جهاز بعينه)، ومحمية بقواعد وصول (Security Rules) تمنع أي شخص غير مسجَّل دخول بحساب مُفعَّل في النظام من قراءة أو تعديل أي بيانات — راجع قسم "ضبط قواعد الحماية" في `FIREBASE_SETUP.md`.
- عند النشر على GitHub Pages فإن **كود الصفحة نفسه** (index.html) يكون علنيًا وقابلًا للعرض من أي شخص، بما في ذلك قيم الربط بمشروع Firebase (وهي قيم تعريف عامة وليست كلمة سر — الحماية الفعلية تأتي من قواعد الوصول في Firebase وليس من إخفاء هذه القيم). **لا تضع** كلمات مرور أو مفاتيح سرية أخرى داخل كود الصفحة.
- يُنصح بمراجعة قائمة المستخدمين من حين لآخر (زر "إدارة المستخدمين") والتأكد من أن كل من يملك صلاحية وصول ما زال ينبغي أن يملكها.

## النشر على GitHub Pages

### الطريقة الأولى: عبر متصفح الويب (الأسهل، بدون أوامر)

1. أنشئ حسابًا على [github.com](https://github.com) إن لم يكن لديك حساب.
2. اضغط **New repository**، واختر اسمًا (مثلاً `leave-system`)، واتركه Public، ثم **Create repository**.
3. في صفحة المستودع الفارغ اضغط **uploading an existing file**.
4. اسحب ملفات `index.html` و`README.md` و`FIREBASE_SETUP.md` وأفلتها، ثم اضغط **Commit changes**.
5. اذهب إلى **Settings → Pages**.
6. تحت **Build and deployment** اختر **Deploy from a branch**، ثم الفرع `main` والمجلد `/ (root)`، ثم **Save**.
7. بعد دقيقة أو دقيقتين سيظهر رابط الموقع أعلى الصفحة بالشكل:
   `https://<username>.github.io/<repo-name>/`

> **تنبيه مهم عند التحديث لاحقًا**: عند رفع نسخة جديدة من `index.html` تأكد أنها تستبدل الملف القديم فعليًا داخل نفس المستودع (وليس رفع ملف بجانبه باسم مختلف قليلًا)، وأن اسم الملف يبقى `index.html` بالضبط. إن لم يظهر التحديث بعد بضع دقائق جرّب فتح الرابط في نافذة تصفح خاصة (Incognito/Private) لاستبعاد ذاكرة التخزين المؤقت للمتصفح.

### الطريقة الثانية: عبر سطر الأوامر (Git)

```bash
cd repo   # المجلد الذي يحتوي على index.html
git init
git add index.html README.md FIREBASE_SETUP.md
git commit -m "Initial commit: leave management system"
git branch -M main
git remote add origin https://github.com/<username>/<repo-name>.git
git push -u origin main
```

ثم فعّل GitHub Pages بنفس خطوات الطريقة الأولى (الخطوة 5 وما بعدها).

> ملاحظة: نسخة هذا المجلد تحتوي بالفعل على مستودع Git مهيأ محليًا — إن كنت تستخدمها كما هي يكفي تنفيذ آخر سطرين (`git remote add` ثم `git push`) بعد إنشاء مستودع فارغ على GitHub.
